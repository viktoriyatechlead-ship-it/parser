# BreedWorld Pedigree Parser

OCR-парсер родословных собак со скриншотов ZooPortal (portalzoo.com).
Обрабатывает PNG-файлы через **Google Cloud Vision API** → выдаёт **XLSX** таблицу с данными собаки и деревом предков до 3 поколений.

---

## Быстрый старт

```bash
# 1. Установить зависимости
npm install

# 2. Положить скрины в папку
# По умолчанию: ../screenshots/all/*.png

# 3. Запустить
node vision-ocr.js

# Или с параметрами:
node vision-ocr.js --dir /path/to/screenshots --output /path/to/result.xlsx --concurrency 10
```

## Входные данные

### Скриншоты

- **Формат:** PNG
- **Источник:** Страница "Происхождение" карточки собаки на ZooPortal
- **Имя файла = кличка собаки** (например: `ABETTA.png`, `ЯЛИКО СМАЙЛ.png`)
- **Разрешение:** ~1400×1300 px (стандарт ZooPortal)

### Как получить скриншоты

Скрины делаются через Puppeteer-скрипт `screenshot-pedigrees.js` (в основном проекте breedworld):
1. Открывает карточку собаки на ZooPortal
2. Переключает на вкладку "Происхождение"
3. Делает скриншот полной страницы
4. Сохраняет как `{КЛИЧКА}.png`

## Как устроен парсер (подробно)

### Шаг 1: Google Cloud Vision API

Каждый PNG отправляется в Vision API с двумя feature-запросами:
- `DOCUMENT_TEXT_DETECTION` — возвращает параграфы с **bounding box** (x, y координаты)
- `TEXT_DETECTION` — возвращает полный текст страницы

**Зачем два запроса:**
- Полный текст нужен для извлечения полей карточки (пол, дата, окрас) — это проще парсить построчно
- Bounding box нужен для определения колонок родословной — без координат невозможно понять кто чей предок

### Шаг 2: Извлечение полей карточки (`extractFromFullText`)

Парсит полный текст **построчно**, ищет ключевые слова:

```
Пол → Кобель/Сука
Дата рождения → ДД.ММ.ГГГГ
Окрас → текст после "Окрас:"
Клеймо → текст после "Клеймо:"
Заводчик → текст после "Заводчик:"
Владелец → текст после "Владелец:"
Питомник → текст после "Питомник:"
№ родословной → регулярка: (РКФ|RKF|FBR|LOF|...) + цифры
```

**Нюансы:**
- Значение может быть на следующей строке (не на той же где ключевое слово)
- Проверяем до 3 строк вперёд от ключевого слова
- Фильтруем навигационный мусор ZooPortal (меню, подвал)

### Шаг 3: Извлечение родословной (`extractPedigree`)

Это самая сложная часть. Родословная на ZooPortal — это **3-колоночная таблица**:

```
┌────────────────┬───────────────────┬──────────────────────┐
│  Col 1         │  Col 2            │  Col 3               │
│  РОДИТЕЛИ      │  ДЕДЫ             │  ПРАДЕДЫ             │
│                │                   │                      │
│  x mid < 45%  │  x mid 45-72%    │  x mid > 72%         │
│  (~470 px)     │  (~790 px)        │  (~1110 px)          │
│                │                   │                      │
│  [Отец]        │  [Дед по отцу]    │  [ОО отца]           │
│                │                   │  [МО отца]           │
│                │  [Бабка по отцу]  │  [ОМ отца]           │
│                │                   │  [ММ отца]           │
│  [Мать]        │  [Дед по матери]  │  [ОО матери]         │
│                │                   │  [МО матери]         │
│                │  [Бабка по матери]│  [ОМ матери]         │
│                │                   │  [ММ матери]         │
└────────────────┴───────────────────┴──────────────────────┘
```

#### 3.1 Определение области родословной

- **Верх:** находим параграф "ПРОИСХОЖДЕНИЕ" + 40px отступ
- **Низ:** imgWidth × 0.75 (подвал сайта)
- **Левый край:** imgWidth × 0.22 (отсекаем боковое меню)

#### 3.2 Разбиение на колонки

Фиксированные границы по **середине** (mid) bounding box:

| Колонка | Граница mid | Примерные x при 1400px |
|---------|-------------|------------------------|
| Col 1 (родители) | < 45% ширины | < 630 px |
| Col 2 (деды) | 45-72% ширины | 630-1008 px |
| Col 3 (прадеды) | > 72% ширины | > 1008 px |

**Почему фиксированные:** ZooPortal использует одинаковый макет для всех карточек. Динамическое определение через gaps ненадёжно — "не указан" записи создают ложные gaps.

#### 3.3 Назначение слотов

В каждой колонке записи **сортируются по Y** (сверху вниз). Порядок сверху вниз **строго** соответствует позициям в родословной:

**Col 1 (2 слота):**
- Первое реальное имя сверху → `sire` (отец)
- Последнее реальное имя снизу → `dam` (мать)

**Col 2 (4 слота, включая "не указан"):**
- Слот 0 → `grandSireS` (дед по отцу)
- Слот 1 → `grandDamS` (бабка по отцу)
- Слот 2 → `grandSireD` (дед по матери)
- Слот 3 → `grandDamD` (бабка по матери)

**Col 3 (8 слотов, включая "не указан"):**
- Слот 0 → `ggSireSS`, Слот 1 → `ggDamSS`
- Слот 2 → `ggSireSD`, Слот 3 → `ggDamSD`
- Слот 4 → `ggSireDS`, Слот 5 → `ggDamDS`
- Слот 6 → `ggSireDD`, Слот 7 → `ggDamDD`

**Важно:** "Отец не указан" / "Мать не указана" сохраняются как **пустые слоты**. Без них нумерация слотов сломается — реальные имена попадут не в те поля.

### Шаг 4: Очистка имён (`cleanName`)

OCR часто добавляет мусор к именам. Парсер чистит:

| Мусор | Пример | Действие |
|-------|--------|----------|
| Номера РКФ | `РКФ 4339014` | Удаляется |
| Даты | `22.12.2019` | Удаляется |
| Описания окраса | `черно-бело-золотой` | Удаляется |
| Пол | `сука`, `кобель` | Удаляется |
| "не указан" | `Отец не указан` | → пустая строка |
| Титулы | `CH.RKF, JCH.RUS` | Строка отклоняется целиком |
| Смесь алфавитов | `KOSTBAR SCHATZ ВАГНЕР` | Оставляется латиница |

### Шаг 5: Фильтрация титулов (`isTitleString`)

Строки вида `CH.RKF, CH.RUS, JCH.RUS, VCH.RKF` — это **титулы**, а не кличка.
Парсер их отклоняет если:
- Строка начинается с `CH.`, `JCH.`, `GrCH.`, `VCH.`
- Строка содержит 2+ ключевых слова титулов (`CH`, `JCH`, `BIS`, `BOB` и т.д.)

## Параметры запуска

```bash
node vision-ocr.js [опции]
```

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--dir` | `../screenshots/all` | Папка с PNG файлами |
| `--output` | `../screenshots/pedigrees_vision.xlsx` | Путь к выходному XLSX |
| `--concurrency` | `5` | Количество параллельных запросов к API |

Переменная окружения:
- `GOOGLE_VISION_API_KEY` — ключ Google Cloud Vision API

## Resume (продолжение после сбоя)

Скрипт **автоматически продолжает** с места остановки:
- При старте проверяет существующий XLSX файл
- Обрабатывает только PNG файлы, которых нет в XLSX
- Промежуточное сохранение каждые 100 файлов

Если скрипт упал — просто запустите снова.

## Точность

| Поле | Точность | Комментарий |
|------|----------|-------------|
| sire (отец) | ~99% | Редко ошибается если титулы длиннее имени |
| dam (мать) | ~98% | Иногда берёт русскую транскрипцию sire |
| Деды (4 поля) | ~50-56% | Зависит от заполненности на ZooPortal |
| Прадеды (8 полей) | ~6-14% | Большинство "не указан" на ZooPortal |

**Низкий % дедов/прадедов** — не ошибка парсера, а отсутствие данных на ZooPortal (много "не указан").

## Известные проблемы и решения

| Проблема | Причина | Решение |
|----------|---------|---------|
| sire = титулы вместо имени | Титулы стоят выше имени на скрине | Фильтр `isTitleString()` |
| dam = русская транскрипция sire | Два абзаца с одним именем в Col1 | Берём первое и последнее (не одинаковые) |
| Мягкий знак → `_` | OCR артефакт | Исправлять в `fix-dirty-names.ts` |
| Прадеды пустые | "Не указан" на ZooPortal | Не ошибка — данных нет |
| Деды попали не в ту позицию | Сломался порядок слотов | Проверить что "не указан" сохраняет слот |
